## What is this?

An embedded front-panel for network rig configuration, built on an ESP32-S3 with a
capacitive touch screen (172×320 px). The device talks to a Raspberry Pi over USB serial
(115 200 baud) and manages Wi-Fi connections, NVS profiles, a web interface and an
xterm.js terminal. It enumerates as a USB composite device: CDC-ACM + HID keyboard + Mass Storage.

| **mDNS** | `rigconsole.local` (STA and AP mode) |

> There must be **no `partitions.csv`** in the sketch folder: the ESP32 core (3.x)
> copies it into the build and it overrides the IDE partition scheme. The old file
> (LittleFS era) had no `fat` partition, so `FFat.begin()` could not mount. Removed in v5.

Pi side lives in [`pi/`](../pi/): `install.sh`, `uninstall.sh`, `rig_daemon.py`
(systemd service `rig-console`), `rig-console.service` (reference copy) and the offline
`pyserial` wheel. After editing anything in `pi/`, run `python3 tools/gen_rigsetup_h.py`
from the repo root and commit `pi/` together with the regenerated `rigsetup_files.h`.
CI fails if `rigsetup_files.h` is out of date with `pi/`.

At boot `littlefs_mgr.ino` writes any missing file to `/rigsetup/` on FFat
(`rig_daemon.py` is stored as `daemon.py` and the wheel as `pyserial.whl`, the names
`install.sh` expects). `fat12_builder.ino` builds the 256 KB FAT12 `RIGSETUP` image in
PSRAM from `/rigsetup/` each time the disk is presented (2 FAT sectors → up to ~250 KB).

## NVS profiles (10 shared slots)

- `MAX_NVS_SLOTS = 10`; each slot: `ssid`, `pass`, `dhcp`, `ip`, `sn`, `gw`, `dns`
- Auto-connect tries slots 0–9 in order; `espActiveSlot` tracks the active one
- `/profiles` manages all slots incl. static IP
- `kbOk()` calls `loadNvsProfiles()` after `saveNvsSlot()`

## Wi-Fi behavior

- `wifiAutoConnect()` scans, then tries slots 0–9, skipping SSIDs not visible
- `wifiConnectSlot(n)` — manual connect (touch or web), **non-blocking since v6.3**:
  `wifiDisconnect()` → `WiFi.mode(apRunning ? AP_STA : STA)` → `WiFi.begin()`;
  `wifiService()` in `loop()` calls `_onConnected()` or times out after
  `WIFI_CONNECT_TIMEOUT_MS` (then `WiFi.disconnect(true)` disables STA only, the AP stays)
- Globals `espConnecting`, `espConnSlot`, `espConnResult`, `espConnTarget` (main .ino);
  web requests set `pendingEspConnect` / `pendingEspDisconnect`, handled in `loop()`
- `startAP()` / `stopAP()` keep STA enabled while `espConnected || espConnecting`
- **No auto-AP** — AP only starts manually from the Advanced menu
- `WIFI_AP_STA` if STA is already up when the AP starts
- `stopAP()`: keeps the web server if STA is still up, otherwise shuts everything down

## Web server

- Runs in **STA mode** too, not only AP mode
- `_webServerRunning` (static in `web_server.ino`) prevents double start
- **`webServerStop()`** is the only correct way to stop it — never `server.stop()` directly
- `wifiDisconnect()` calls `webServerStop()` **only when the AP is not running** (v6.3)
- Routes are registered once (`_routesRegistered`); a restart only calls `server.begin()`

## Serial protocol (115 200 baud, newline-terminated ASCII)

### ESP32 → Pi

```
HELLO                                    — on boot / reconnect
CMD:GET_STATUS                           — polled every 5 s
CMD:CONNECT:<profile>                    — user picked a Pi profile
CMD:ADDWIFI:<ssid>:<pass>                — add simple profile on Pi
CMD:ADDWIFI_FULL:<s>|<pw>|<dhcp>|<ip>|<sn>|<gw>|<dns>
CMD:GET_PROFILES_FULL                    — request full profile list
CMD:SCAN_WIFI                            — Pi-side Wi-Fi scan
CMD:START_AP / CMD:STOP_AP               — AP state notification
CMD:TERM_OPEN                            — spawn PTY when terminal WS connects
TERM:IN:<b64>                            — terminal input
CTL:RESIZE:<cols>:<rows>                 — terminal size
```

### Pi → ESP32

```
ACK                      — reply to HELLO
STATUS:SSID:<ssid>       — real Wi-Fi SSID from nmcli (or NONE) → activeSSID (display)
STATUS:CONN:<name>       — NetworkManager connection name (or NONE) → activeConn
                           (profile matching, CMD:CONNECT)
STATUS:IP:<ip>           — active IP (or NONE)
STATUS:PORT:<device>     — USB port in use (e.g. ttyACM0)
STATUS:SYS:k=v|k=v|…     — v6.3 Pi system info, sent with every status reply. Keys:
                           host model os code arch kernel daemon up load temp
                           mem(used/total MB) disk(used/total GB) thr(hex) wifi(dBm) ntp(yes/no).
                           Values ASCII, '|' replaced by '/', max 48 chars, empty keys omitted.
                           ESP replaces its whole table (MAX_PI_SYS 24) on each line;
                           unknown keys are kept and shown raw on /info.
PROFILES:<p1>,<p2>,...   — NM connection names (stored in piProfiles[].ssid)
PROFILES_FULL:...        — full profile list
OK:CONNECT:<profile> / ERR:CONNECT:<profile>
OK:ADDWIFI:<ssid>    / ERR:ADDWIFI:<ssid>
OK:ADDWIFI_FULL:...  / ERR:ADDWIFI_FULL:...
SCAN_RESULT:...          — Pi-side Wi-Fi scan result
TERM:OUT:<b64>           — terminal output
```

### Installer (install.sh → ESP32, during Install on Pi)

```
RIG:INSTALL_START / RIG:INSTALL_DEPS / RIG:INSTALL_DAEMON / RIG:INSTALL_SERVICE
RIG:INSTALL_DONE         — ESP ejects MSC, waits 3 s, sends HELLO (auto-connect)
RIG:INSTALL_ERR_NOROOT / RIG:INSTALL_ERR_COPY / RIG:INSTALL_ERR_SERVICE
RIG:INSTALL_ERR_DEPS     — v6: pyserial could not be installed (pip, apt and wheel unzip failed)
```

CLI mode (v6) also uses these one-shot replies, echoed by commands the ESP types:
`RIGPING:.:<port>` (shell reached + layout check), `ACMOK:<n>` (port probe),
`SUDOOK` (sudo authenticated), `MNTOK` (RIGSETUP mounted at `/mnt/rigsetup`).

Polling: `POLL_INTERVAL_MS = 5000`; `PI_TIMEOUT_MS = 15000` → `piConnected = false`.

## Terminal (xterm.js over WebSocket)

```
Browser                 ESP32-S3                  Pi (rig_daemon.py)
  │──btoa(key)──WS──────▶│──TERM:IN:<b64>──serial──▶│  PTY
  │◀─raw b64────WS───────│◀─TERM:OUT:<b64>─serial───│
  │ atob() → Uint8Array → term.write(bytes)
```

- ESP → browser: raw base64 string as WS text frame (not JSON)
- `termFit()` measures a hidden `<span>` and calls `term.resize()` — **no FitAddon**
  (it is not in `xterm_js.h`)
- `CTL:RESIZE` sent on WS open and via ResizeObserver; daemon applies TIOCSWINSZ
- Auto-reconnect: `ws.onclose` → `setTimeout(wsConnect, 2000)`

### Quick Buttons

- 25 buttons in a **vertical list** (`flex-direction:column`) — not a grid
- Each maps to a macro id; stored in NVS (`"qbtns"`, `"q0".."q24"`, value = id or -1)

### Macros & menus (v5)

Stored on FFat, handled entirely client-side (the ESP only stores QB ids):

```
macros.json  { "macros": [{id, name, cmd, cr}], "nextId": N }
menus.json   { "menus":  [{id, label, entries: [...]}], "nextId": N }
  entry: {type:"macro", ref:id} | {type:"sep"} | {type:"submenu", label, entries:[]}
```

`/macros` is a full-page editor: macro library with search, click or drag macros into
menus/submenus, separators, 25 QB slots, import/export as JSON. The terminal menu item
"Edit macros & menus…" opens it in a new tab. Examples: [`examples/`](../examples/).

### `gen_terminal_html.py`

The ONLY source for `terminal_html.h`. Edit the `.py`, run `python3 gen_terminal_html.py`,
commit both. The script asserts: no FitAddon, `termFit` present, vertical QB present.

## FFat storage

- Arduino IDE → Tools → Partition Scheme → **"16M Flash (2MB APP/12.5MB FATFS)"**
- No custom `partitions.csv` — and none may exist in the sketch folder (it would override the scheme)
- Changing the partition table requires a **USB flash** from Arduino IDE — OTA only replaces the app
- Mounted in `littlefs_mgr.ino` (FFat, despite the file name)
